# Контекст для разработки

Документация не для пользователя (она в корневом `README.md`), а для того, кто будет
править этот код дальше — человека или модель. Здесь то, чего не видно из самого кода:
почему сделано так, что уже пробовали, и на чём тут легко обжечься.

## Команды

```bash
npm run dev        # сервер + Vite с hot reload, интерфейс на :5273, API на :8787
npm run app        # то же самое, но в окне Electron с треем
npm run check      # все проверки, ~75 секунд
npm run typecheck  # tsc --noEmit
npm run app:build  # установщик и portable в release/
```

## Правила, которые стоит соблюдать

**Никогда не переписывать исходники через PowerShell `Get-Content` / `Set-Content`.**
Windows PowerShell 5.1 читает UTF-8 как cp1251 и пишет обратно с BOM — весь текст на
русском превращается в мусор. Это уже случилось однажды с `server/probe.ts`, и
восстановление потребовало отдельного скрипта, разбирающего повреждение побайтово.
Правьте файлы редактором (`Edit`/`Write`) или Node; `[IO.File]::ReadAllText` с явным
`UTF8Encoding($false)` допустим, если очень нужно.

**Утверждение без проверки не считается сделанным.** Каждое нетривиальное поведение
здесь подкреплено скриптом в `scripts/`, который поднимает то, что нужно, на loopback и
проверяет именно свойство, а не «не упало». Дважды выяснялось, что проверка не могла
провалиться в принципе — см. `pitfalls.md`.

**Комментарии объясняют «почему», а не «что».** В коде много неочевидных решений,
продиктованных поведением сетей и Windows; каждое подписано. Не удаляйте такие
комментарии при рефакторинге — они дороже кода, который поясняют.

**Русский в интерфейсе и выводе, английский в комментариях и именах.** Так сложилось,
так и продолжайте: пользователь видит только русский, разработчик — только английские
идентификаторы.

`tsconfig.json` включает `noUnusedLocals` и `noUnusedParameters`: мёртвый импорт ломает
сборку, а не копится.
